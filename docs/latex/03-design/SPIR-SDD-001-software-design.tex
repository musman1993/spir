\section{Introduction}
This Software Design Description explains how SPIR release \SPIRRelease\ meets the requirements in SPIR-SRS-001. It is
the starting point for a developer or vendor taking the code forward. Diagrams use UML notation drawn in TikZ; their
sources live in \fpath{docs/latex/diagrams/}.

\subsection{Design goals}
\begin{enumerate}
  \item \textbf{Integrity first}: history is never overwritten, approved versions are immutable and the audit trail is
    append-only, enforced by the database rather than by application code alone.
  \item \textbf{Replaceable parts}: database, storage, authentication, OCR engine and devices sit behind small
    interfaces, so the proof of concept can move to company infrastructure without rewriting business rules.
  \item \textbf{One rule set}: the shipment form and the CSV import use the same import engine, and the label check uses
    one versioned comparison engine.
  \item \textbf{No secrets in the browser}: the web app is static and public; everything sensitive runs in the API.
\end{enumerate}

\section{Architecture}
\subsection{Style}
A \textbf{modular monolith}: one API deployable with clear modules, a pure domain engine with no I/O, and providers
for infrastructure. The web app is a single-page application that talks to the API over REST.

\subsection{Invariants enforced by the database}
\begin{itemize}
  \item Approved versions cannot be updated (trigger raises \emph{immutable}). In release \SPIRRelease\ there is no
    approval step: every save is written straight in as \code{APPROVED}, so \code{APPROVED} means \emph{live}. An edit
    adds a new \code{APPROVED} version and marks the previous one \code{SUPERSEDED} in the same transaction; QR scans
    show the new version at once.
  \item Audit events cannot be updated or deleted (trigger raises \emph{append-only}).
  \item At most one APPROVED and one open version per record, and one ACTIVE QR token per record (partial unique indexes).
  \item Every record references exactly one product; every product one supplier (foreign keys).
\end{itemize}

\section{API design}
REST over HTTPS under \code{/api/v1}; JSON bodies; errors as \code{\{error: \{code, message, details\}\}} with HTTP
401 (sign in), 403 (wrong portal), 404, 409, 410 (revoked QR), 422 (validation), 429 (rate limit). Every response
carries an \code{X-Correlation-Id}. The contract is in \fpath{api/openapi.yaml}.

\section{Security design}
\subsection{Authentication}
\code{POST /auth/login} checks the fixed credentials of the chosen portal with constant-time comparison and a short
delay on failure. It returns a token \code{base64url(\{u, exp\}).HMAC-SHA256}, valid for 12 hours, keyed with a
secret derived from \code{QR\_TOKEN\_KEY}. The API loads the account on every request, so deactivating an account
takes effect at once. The web app stores one token per portal and picks it from the address.

\subsection{Authorization}
{\small\zebra
\begin{tabularx}{\linewidth}{@{}Y>{\centering\arraybackslash}p{2cm}>{\centering\arraybackslash}p{2cm}>{\centering\arraybackslash}p{2cm}@{}}
  \thead\hd{Capability} & \hd{Supplier} & \hd{Company} & \hd{Public}\\
  Profile, shipments, CSV, certificates upload & \yes & \no & \no\\
  Print, replace, revoke QR labels & \yes{} own & \no & \no\\
  Read shipments and products & \yes{} own & \yes{} all & \no\\
  Scan a QR label, open its certificates & \yes & \yes & \yes\\
  Label checks, discrepancies & \no & \yes & \no\\
  Supplier list, audit API & \no & \yes & \no\\
\end{tabularx}}

Supplier scope is enforced in each query (\code{supplier\_id = account supplier}); another supplier's record answers 404
so that its existence is not revealed.

\subsection{Protection of data}
\begin{itemize}
  \item \textbf{QR tokens}: 80 random bits (Crockford base32); stored as SHA-256 for lookup and AES-256-GCM ciphertext for
    reprinting; old 256-bit tokens still resolve. Rate limit 60 look-ups per minute per caller address.
  \item \textbf{Certificates}: private bucket; links signed for 300 seconds; uploads checked for size, extension and
    sniffed content type; SHA-256 stored.
  \item \textbf{Transport}: HTTPS; Postgres with \code{sslmode=verify-full}; CORS limited by \code{ALLOWED\_ORIGINS}.
  \item \textbf{Secrets}: only in \code{.env} (git-ignored), GitHub Actions secrets and Neon variables.
\end{itemize}

\subsection{Threats and mitigations}
{\small\zebra
\begin{xltabular}{\linewidth}{@{}L{3.4cm}Y L{3.6cm}@{}}
  \thead\hd{Threat} & \hd{Mitigation in 0.5} & \hd{Residual risk}\\\endhead
  Guessing the shared password & Short delay, audit of sign-ins. & \High\ fixed admin/admin; replace with real accounts.\\
  Reading data by guessing QR tokens & 80-bit random tokens, rate limit, audit. & \Low\\
  A leaked QR link & Revoke or replace the label. & \Med\ scans are public by decision.\\
  Supplier reading another supplier & Scope in every query; 404. & \Low\\
  Tampered session & HMAC signature, expiry, account reloaded. & \Low\\
  Malicious upload & Type sniffing, size limit, private storage. & \Med\ no malware scan.\\
  Lost history & Immutable versions, append-only audit (triggers). & \Low\\
\end{xltabular}}

\section{Label validation engine}
\subsection{Pipeline}
\begin{enumerate}
  \item \textbf{Capture} (browser): photo or camera, manual crop, upscaling to about 2000\,px (at most 4×), greyscale and
    contrast; image quality warnings.
  \item \textbf{Read} (browser): Tesseract.js words with confidences; ZXing barcodes and QR codes on the same image.
  \item \textbf{Extract} (\fpath{domain/extract.ts}): profile aliases (exact, then fuzzy at line start), value patterns
    and fallbacks; barcodes mapped by pattern; a barcode beats a weak OCR read, a confident conflicting read becomes an
    alternative.
  \item \textbf{Resolve} (\code{resolver-v2}): part + (PO or heat), or PO + (heat or line); line breaks ties; several
    candidates go to the user. A SPIR QR on the label resolves directly.
  \item \textbf{Compare} (\code{compare-v2}): per attribute method (identifier, code, date, decimal, integer, quantity,
    name, text). Exact long identifiers match even at low confidence; confusable characters, junk characters, cut-off
    reads and a lost slash go to review, never to a match.
  \item \textbf{Overall} (\code{overall-v2}): a critical exception is never hidden by matches; a non-critical field
    missing from the label is ignored.
\end{enumerate}
Rule versions are stored with every run: \code{compare-v2/overall-v2/resolver-v2}.

\subsection{Label profile RECEIVING\_LABELS v1}
Covers the company receiving label (Item, Purchase Order \#, Line \#, Qty, Description) and the supplier label (supplier
name, Part No with revision, PO No with LINE, Qty \code{a/b}, Heat No, Pattern, RT). Patterns: PO exactly 10 digits;
part number \code{[0-9]\{1,2\}[A-Z][0-9A-Z]\{6,10\}}; country of origin fallback ``MADE IN \ldots''.

\section{QR label rendering}
\begin{itemize}
  \item Matrix from \code{qrcode}; error-correction level chosen as the strongest of H, Q, M that does not enlarge the
    code beyond level M.
  \item Own SVG renderer: 2-module border in the image plus label padding (at least 4 in total); logo in an odd-sized,
    grid-aligned cut-out of at most 20\% of the width.
  \item Verification: every code is rasterised and decoded with ZXing; on failure the logo shrinks (20, 16, 12\%) or is
    removed.
  \item Sheets: A4 templates in millimetres (\code{@page sheet \{size: A4; margin: 0\}}), start position, printer offset;
    PNG at 300\,dpi at the label's real size.
\end{itemize}

\section{Front-end design}
\begin{itemize}
  \item Routes: \code{/\#/supplier/*}, \code{/\#/company/*}, public \code{/\#/t/:token}; anything else goes to the company portal.
  \item One \code{PortalSession} per portal; the API client picks the token from the address.
  \item Visual system: deep-blue glass rail, warm mist canvas, frosted cards (blur 14\,px, 18\,px radius), brand colour
    tokens in \fpath{web/src/styles.css}; status colours with darker same-hue text for 4.5:1 contrast; Figtree and IBM Plex Mono.
  \item Device adapters in \fpath{web/src/devices}: camera (\code{getUserMedia}), barcode (ZXing), OCR (Tesseract.js
    worker), keyboard-wedge scanner (fast keystrokes ending in Enter), image preprocessing.
\end{itemize}

\section{Technical debt}
\begin{itemize}
  \item Fixed credentials and shared accounts (replace with RBAC and SSO).
  \item In-memory rate limiter per function instance (move to a shared store).
  \item Unused draft/submit helpers in \fpath{api/src/modules/versioning.ts} kept for the workflow's return.
  \item \fpath{api/openapi.yaml} carries a v0.5 change note; the path list needs a full refresh.
  \item No metrics or tracing; audit is the only operational record.
\end{itemize}
