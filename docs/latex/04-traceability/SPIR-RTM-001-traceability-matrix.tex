\section{Purpose and how to read this matrix}
This matrix shows, requirement by requirement, how far the SPIR proof of concept meets the \emph{\SPIRSpec}.
It is the reference for scope discussions with the vendor and for deciding what the next phases must deliver.

Each requirement has one status:

{\small
\begin{tabularx}{\linewidth}{@{}L{3.1cm}Y@{}}
  \Done & Built and covered by automated tests or verified in the browser.\\
  \Partial & Part of the requirement is built; the evidence column says what is missing.\\
  \Deferred & Built in an earlier release and removed in release 0.5 by a stakeholder decision. The code is kept on the git branch \fpath{archive/roles-and-review}.\\
  \Deviation & Deliberately different from the specification, by a stakeholder decision, with the risk recorded in SPIR-SCP-001.\\
  \NotStarted & Not built in this proof of concept; planned for a later phase.\\
  \OpenItem & A non-functional target the specification asks the project to define; not yet set.\\
\end{tabularx}}

\begin{keypoint}[Maintaining this matrix]
The rows come from \fpath{docs/latex/04-traceability/rtm.csv} (one line per requirement, fields separated by \code{|}).
When a change moves a requirement forward, edit its status and evidence in that file in the same pull request; the
summary counts below are calculated when the PDF is built.
\end{keypoint}

\subsection{What the numbers say}
\begin{itemize}
  \item \textbf{Strongest areas:} product and traceability data, documents, QR codes and the label-OCR check, which
    together hold most of the implemented requirements. The OCR area meets all P0 requirements of the specification
    except automatic perspective correction and unknown-profile onboarding.
  \item \textbf{Workflow is deferred, not missing:} the full draft, submit, review, approve or reject cycle was built
    and tested in releases 0.1 to 0.4. Release 0.5 publishes every save at once by decision, so these requirements
    show as deferred.
  \item \textbf{Two deliberate deviations:} \req{FR-QR-003} and \req{FR-DOC-005}. QR scans and the certificates they
    link to are open to anyone with the label. This must be confirmed or reversed before real data goes live.
  \item \textbf{Largest gap:} X12 EDI (all 14 requirements), which the specification describes as a separate intake
    channel and which was out of scope for this proof of concept.
  \item \textbf{Non-functional targets} (availability, performance, recovery, retention) still have to be agreed; the
    application is ready to be measured against them.
\end{itemize}
