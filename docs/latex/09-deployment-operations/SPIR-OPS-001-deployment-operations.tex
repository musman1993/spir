\section{Prerequisites}
\begin{itemize}
  \item GitHub account with access to \href{\SPIRRepoURL}{\SPIRRepo}; Codespaces enabled.
  \item Neon project with Postgres branch \code{production}, Object Storage bucket \code{spir} and a function slot.
  \item For local machines instead of Codespaces: Node 24, npm, and optionally the Neon CLI (\code{npm i -g neon}).
  \item To build the documentation: a TeX distribution with \code{latexmk} (TeX Live 2023 or later).
\end{itemize}

\section{Running in a Codespace}
\subsection{Quick start (no database needed)}
\begin{cmd}
git pull
npm install
npm run dev:memory\qquad\# demo data;\quad npm run dev:empty for an empty registry
\end{cmd}
Open the \ui{Ports} tab, open port \textbf{5173}, and add \code{/\#/supplier} or \code{/\#/company} to the address. Both
portals sign in with \code{admin} / \code{admin}. Keep the ports \emph{private} (GitHub asks for sign-in) when real
data is present.

\subsection{Against the Neon database}
\begin{enumerate}
  \item \code{npm run db:connect} --- paste the connection string from Neon console \(\rightarrow\) project \(\rightarrow\)
    \ui{Connect} (branch \code{production}, database \code{neondb}). Input is hidden; the connection is tested before
    \code{.env} is written.
  \item Generate the QR key once and put it in \code{.env} as \code{QR\_TOKEN\_KEY}:
\begin{cmd}
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
\end{cmd}
  \item Optional: Neon Object Storage keys (\code{AWS\_*}, \code{SPIR\_BUCKET}); without them files go to \code{.data/storage}.
  \item \code{npm run db:setup} (migrations, then demo seed) and \code{npm run dev}.
\end{enumerate}

\begin{warningbox}[Never share .env]
\code{.env} holds the database password, storage keys and QR key. It is git-ignored; never paste it into chat,
tickets or e-mail. If it was shared, rotate every value in it (see section~\ref{sec:rotate}).
\end{warningbox}

\section{Database}
\begin{itemize}
  \item \code{npm run db:migrate} applies new files from \fpath{api/db/migrations/} in order and records them in
    \code{spir.schema\_migrations}. Safe to run repeatedly.
  \item \code{npm run db:seed} loads \fpath{seed/spir_seed.csv} plus \fpath{seed/local/*.csv}.
  \item \code{npm run db:reset} drops and recreates schema \code{spir} --- \textbf{all data is lost}.
  \item New migration: add \code{007\_<name>.sql}, start with \code{SET LOCAL search\_path TO spir, public;}, never edit an
    applied file.
\end{itemize}
\begin{caution}[Status at the time of writing]
The Neon \code{production} branch had only \code{001\_init.sql} applied. Run \code{npm run db:setup} once to apply
002--006 and load the demo data.
\end{caution}

\section{Routine operations}
\subsection{Rotating secrets}\label{sec:rotate}
\begin{enumerate}
  \item \textbf{Database password}: Neon console \(\rightarrow\) Roles \(\rightarrow\) \code{neondb\_owner} \(\rightarrow\)
    reset; then \code{npm run db:connect} in each Codespace.
  \item \textbf{Storage keys}: Neon console \(\rightarrow\) Credentials: revoke the old key, create a new pair; update
    \code{.env} and the Neon function variables.
  \item \textbf{QR key}: changing it stops reprinting of existing labels (scans keep working). Change it only before
    labels are printed, or reissue labels afterwards (rotate each label).
  \item \textbf{Sessions}: changing \code{QR\_TOKEN\_KEY} also signs everyone out.
\end{enumerate}

\subsection{Changing the address printed in QR codes}
Set \code{PUBLIC\_APP\_URL} (and the \code{SPIR\_WEB\_URL} variable), redeploy, then reprint labels. Printed labels keep
the address they were printed with.

\subsection{Company logo on labels}
Put the logo in \fpath{web/public/brand/} as \code{logo.png} (square, white or transparent background) or
\code{logo.svg}; PNG wins if both exist. Reload the QR labels page; the scan check confirms every code still reads.

\subsection{Real data}
Real shipment CSVs go in \fpath{seed/local/} and real label photos in \fpath{api/test/fixtures/local/}; both are
git-ignored. Never commit real POs, supplier names or photos: the repository is public.

\subsection{Backups}
Neon keeps point-in-time history for the branch according to the plan. Before risky changes, create a Neon branch
(snapshot) of \code{production}. A restore procedure and RPO/RTO targets are still to be agreed (SPIR-SCP-001).

\section{Troubleshooting}
{\small\zebra
\begin{xltabular}{\linewidth}{@{}L{4.2cm}Y Y@{}}
  \thead\hd{Symptom} & \hd{Cause} & \hd{Fix}\\\endhead
  \code{npm: command not found} in a new Codespace & Codespace in recovery mode (old container). & Rebuild the container (Command Palette: \emph{Codespaces: Rebuild Container}); the dev container now installs Node 24.\\
  \code{getaddrinfo ENOTFOUND HOST}, or ``DATABASE\_URL is still the example placeholder'' & \code{.env} still has \code{USER:PASSWORD@HOST}, or an old terminal variable overrides it. & \code{npm run db:connect}; or \code{unset DATABASE\_URL DATABASE\_URL\_UNPOOLED} and check \code{.env}.\\
  SSL mode warning from \code{pg} & \code{sslmode=require} in the URL. & Use \code{sslmode=verify-full}.\\
  \code{EADDRINUSE :::8787} & Another \code{npm run dev*} is still running. & Ctrl+C in that terminal, or \code{npx kill-port 8787 5173}.\\
  Phone asks for GitHub sign-in when scanning & Label printed with a Codespace address. & Set \code{PUBLIC\_APP\_URL} to the permanent address and reprint.\\
  Camera does not start & No permission, or not HTTPS. & Allow the camera; use the HTTPS forwarded address.\\
  ``Set up your supplier profile first'' & Supplier account has no supplier yet. & Supplier portal \(\rightarrow\) Profile.\\
  CSV rejected & At least one row invalid. & Fix every row listed; the import is all-or-nothing.\\
  QR shows ``revoked'' & Label was replaced or revoked. & Print the current label from the shipment page.\\
\end{xltabular}}

\section{Support checklist for a new release}
\begin{enumerate}
  \item All CI checks green; documentation builds.
  \item Update \fpath{docs/latex/shared/project.tex} (release, date), release notes, traceability CSV.
  \item Merge to main; check deploy-api and deploy-web runs; migrations applied.
  \item Smoke test: sign in to both portals, add a shipment, scan its label on a phone, run a label check.
\end{enumerate}
